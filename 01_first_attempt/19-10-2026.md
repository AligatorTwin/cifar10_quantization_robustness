# 19 Oct 2026

Summary of the first attempt. File was Untitled12.ipynb.

## What it tried to do

• Train a small model on images.
• Test it.
• Quantize it to 8 bit.
• Test it again.
• Compare the two.
• Test it under attacks and bad images as well.

## What was really inside it

• One long script in a single cell. About 300 lines.
• Its own fake quantization. Rounding done in float. Weights stayed float32.
• A synthetic dataset. Random noise with a light stripe.
• A big attack suite. FGSM, PGD, noise, blur, darkening, resizing.
• Cell 2 pulled CIFAR 10 and copied cat and dog photos into folders.
• Cell 3 gave up on that and drew its own pictures with PIL. Ellipses for cat, rectangles for dog.
• Cell 4 failed. Import of a file named evaluation. No such file existed.
• Cell 5 wrote the script out to evaluation.py while running, then imported it.
• That import hid ipykernel to force the real data path. It did not work.
• The key still existed, so the demo path always ran and every real data argument got ignored.
• Cells 6 to 8 read metrics.csv and drew the plots.

## What went wrong

• The import error killed the first real run.
• The demo path always won. It trained on about 1000 stripe images, not photos.
• Drawn shapes are not a dataset. Two shapes are too easy to separate.
• Quantized copies got extra training. The 32 bit model did not. Two things changed at once.
• No real 8 bit model was ever made. Nothing was packed. Nothing got smaller or faster.
• The input wrapper tested for a global named mean. That test means nothing inside a method.
• The model expected 32 by 32 inputs. The data was 224 by 224.
• 2, 4, 6 and 8 bit all in one run. Hard to read.
• Most of the code was attack testing. Nothing to do with quantization.

## Outcome

• 100 percent on stripe images. That number means nothing.
• No 8 bit model. No size number. No speed number.
• The pipeline idea was fine. The code was not.
